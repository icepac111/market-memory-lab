# Scientific Constitution

## First principles

1. No estimator is truth.
2. No analogy is law.
3. No correlation is causation.
4. No in-sample fit is discovery.
5. No forecast matters without a baseline.
6. No statistical effect guarantees economic value.
7. No AI output becomes numerical ground truth.
8. No failed experiment disappears.
9. No number appears without provenance.
10. No conclusion is protected from falsification.

## Required evidence contract

Every reported result must identify:

- research question
- hypothesis
- source
- license or access conditions
- asset identifier
- asset class
- venue
- currency
- timezone
- observation timestamp
- retrieval timestamp
- sampling frequency
- mathematical definition
- estimator
- estimator parameters
- assumptions
- uncertainty method
- null model
- baseline
- validation design
- data cutoff
- sensitivity analysis
- known limitations
- falsification condition
- code version

## Permitted conclusion states

- Supported
- Mixed
- Unsupported
- Insufficient evidence
- Abstain

These states must not be silently converted into personalized Buy, Sell,
or Short instructions.

## Missing information

Unknown information remains unknown.

Missing fields must not be guessed, inferred from unrelated records, or
filled with synthetic values unless the synthetic status is explicit.

## Failed and negative results

Failed experiments, null results, unstable estimates, and unsuccessful
replications remain part of the research record.

They must not be deleted merely because they weaken a preferred theory.

## Physics-inspired interpretation

Information-theoretic quantities may be used when formally defined.

Temperature, energy, equilibrium, phase transition, dissipation,
susceptibility, hysteresis, and related terms are model-specific
analogies unless the project explicitly establishes:

- financial state variables
- mathematical mapping
- units
- invariance properties
- boundary conditions
- null behavior
- empirical interpretation
- falsification conditions

## Reproducibility

A result is not reproducible merely because code exists.

Reproducibility requires identifiable data, environment information,
parameters, random seeds where applicable, a data cutoff, code version,
and executable tests.
